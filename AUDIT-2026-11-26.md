## The History Before the Defect List

Nothing here was a bad decision at the time. Three constraints compounded during the rapid v0.2.0 → v0.3.0 buildout:

1. **Guards were ported from Python to Node without carrying over the hardened edge cases.** `verify.mjs` re-implemented `stripComments`, `SECRET_RE`, and `gitignoreIgnoresEnv` from scratch in JS, reintroducing bugs already fixed in `benchmark/checks.py` and `scripts/audit_history.py` (hash-in-string comment stripping, missing `sk-proj-`/`sk-ant-` hyphenated keys, nested `.env` blindness).
2. **Adversarial controls were tested only against friendly fixtures (Class 3 / Class 14).** `test_verify.mjs` verified that each new v0.3.0 slice catches the exact happy-path bad case it was written for, without attacking the guard itself (e.g., forging `GATE-RECEIPT.json` with `status: "PASS"` + `checks: [FAIL]`, passing `test.skip()` to `test-count-floor`, passing a 404-for-everyone route to `server-idor`, or sending `rgba(0,0,0,0.1)` to `contrastRatio`).
3. **Harness integration (`hook-check`, `init --git-hook`, `install --with-hook`, CI) assumed clean POSIX happy paths.** `hook-check` never reads Claude Code's `stdin` (`stop_hook_active`), `killProcessTree` only kills `/bin/sh` on POSIX, `init --git-hook` assumes `.git` is a directory with no existing hook, and CI runs only on `ubuntu-latest` — hiding a live Windows UTF-8 test failure in `audit_history.py`.

## Confirmed Findings (Bug-Bounty & `/kee` Defect Classes)

### CRITICAL — Security & Gate-Bypass Flaws

#### V1 — **Critical (Gate Forgery / Trust Boundary)** — Classes 4, 14, Gate E: `checkReceipt()` trusts `status: "PASS"` without validating `checks`, and `treeHash` omits `baseline.json` & symlinks
- **Where:** `one-shot/scripts/verify.mjs:107-142, 163-189`
- **Mechanism:**
  1. `checkReceipt()` checks ONLY `receipt.status === "PASS"` and `receipt.treeHash === computeTreeHash(root).treeHash`. It never verifies that `receipt.checks` is a non-empty array, that zero checks have `status === "FAIL"`, or that `receipt.summary.fail === 0`.
  2. `computeTreeHash()` skips `one-shot-work/` and adds back ONLY `one-shot-work/contract.json` — it omits `one-shot-work/baseline.json` (and custom `--contract` paths). Tampering with `baseline.json` does not invalidate `treeHash`.
  3. `walkFiles()` uses `entry.isFile()` and ignores symlinks (`entry.isSymbolicLink()`), so symlinked source files are invisible to `computeTreeHash`, `secrets-scan`, `diff-scope`, and `countTestDefinitions`.
- **Live probes (CONFIRMED 2026-11-26):**
  - **P1:** Wrote `{"status":"PASS","treeHash":"<live>","checks":[{"id":"deliverables","status":"FAIL"}]}` on a project with a missing deliverable → `checkReceipt()` returned **`{ ok: true, code: "OK" }`**!
  - **P15:** Overwrote `one-shot-work/baseline.json` (`testCount: 10` → `0`, `files: {}`) → `computeTreeHash()` returned the **exact same hash** (`5312dcf0c548` === `5312dcf0c548`).
- **Blast radius:** Any agent or script can bypass `hook-check` / `--check-receipt` with a 1-line forged receipt containing failing or zero checks; brownfield `baseline.json` tampering goes undetected.
- **Fix:** Validate receipt schema strictly in `checkReceipt()` (`Array.isArray(receipt.checks) && receipt.checks.length > 0`, every check has valid `id`/`status`, zero `FAIL` checks, `summary.fail === 0`, and if `contract.json` has `deliverables`/`testCmd`/`buildCmd`/`criteria`, assert corresponding check IDs are present). Include `baseline.json` (and any custom contract path) in `computeTreeHash()`. Explicitly handle or reject symlinks in `walkFiles()`.

#### V2 — **Critical (Secret Scanner Bypass)** — Classes 4, 17: `SECRET_RE` misses modern OpenAI (`sk-proj-`) and Anthropic (`sk-ant-`) keys; `stripComments` `#` regex blinds Python/YAML/TOML/Shell scanning
- **Where:** `one-shot/scripts/verify.mjs:40, 80-82`
- **Mechanism:**
  1. Line 40 uses `\\bsk-[A-Za-z0-9]{20,}\\b` — **no hyphens or underscores**. Real OpenAI project keys (`sk-proj-...`) and Anthropic keys (`sk-ant-api03-...`) have a hyphen at char 4 (`proj-`, `ant-`), so they **never match**. (Compare `scripts/audit_history.py:133`, which uses `[A-Za-z0-9_-]{8,}`.)
  2. Lines 80–82 run `text.replace(/#[^\n]*/g, " ")` on `.py`, `.yaml`, `.yml`, `.toml`, `.sh`, `.ini`, `.cfg` without skipping string literals — the exact A1 bug from `checks.py`, now in `verify.mjs`. Any `#` inside a string (hex color `"#ffffff"`, URL fragment `"https://x/#y"`) erases the rest of the line, blinding `secrets-scan`.
- **Live probes (CONFIRMED 2026-11-26):**
  - **P2:** `app.js` containing both `sk-proj-abc123def456ghi789jkl012mno345` and `sk-ant-api03-abc123def456ghi789jkl012` → `secrets-scan` returned **`PASS`** (`no secret literals found`).
  - **P3:** `app.py` containing `COLOR = "#ffffff"; KEY = "AKIAIOSFODNN7EXAMPLE"` → `secrets-scan` returned **`PASS`** (`no secret literals found`).
- **Blast radius:** Production OpenAI/Anthropic API keys and any Python/YAML/TOML secret on a line with a hex color or URL fragment ship right through the release gate.
- **Fix:** Change `sk-` pattern to `\\bsk-(?:proj-|ant-|live-|test-)?[A-Za-z0-9_-]{20,}\\b` (and add `sk_live_`, `gho_`, `glpat-`). Make hash-comment stripping string-aware (`"(?:\\.|[^"\\\n])*"|'(?:\\.|[^'\\\n])*'|(#[^\n]*)`).

#### V3 — **Critical (Stop-Hook Infinite Loop)** — Classes 12, 16: `hook-check` ignores Claude Code's `stop_hook_active` stdin payload, contradicting `SKILL.md`'s 3-retry `BLOCKED` exit
- **Where:** `bin/one-shot.mjs:281-306` vs `one-shot/SKILL.md:27`
- **Mechanism:** `SKILL.md:27` mandates: *"Retry cap: 3 failed attempts on one criterion -> stop, record the blocker in `one-shot-work/DIAGNOSIS.md`, and report `BLOCKED`."* However, `cmdHookCheck` never reads `stdin` for Claude Code's Stop-Hook JSON (`{ "stop_hook_active": true, "cwd": "..." }`) and never honors `DIAGNOSIS.md` / `stop_hook_active`. Whenever a run hits an unfixable blocker, `hook-check` exits `2` forever, trapping the agent in an infinite Stop-Hook loop.
- **Live probe (CONFIRMED 2026-11-26):**
  - **P11:** Piped `{"stop_hook_active": true}` to `node bin/one-shot.mjs hook-check --dir <blocked-proj>` → exited **`2`** (`one-shot BLOCKED`).
- **Fix:** Read `stdin` (non-blocking / when `!process.stdin.isTTY`) in `cmdHookCheck`: honor `payload.cwd` when `--dir` is not explicitly passed, and when `payload.stop_hook_active === true` (and/or `DIAGNOSIS.md` records a retry-cap escalation), allow stopping cleanly (exit `0` with a warning on stderr) instead of looping forever.

### HIGH — Broken Guards, False Greens & Destructive CLI Bugs

#### V4 — **High (False Green Adversary)** — Classes 14, 21, Gate E: `server-fuzz` claims prototype-pollution protection without testing it and misses headerless XSS; `server-idor` passes on 404-for-everyone and skips `PATCH`/`DELETE`
- **Where:** `one-shot/scripts/verify.mjs:485-545`
- **Mechanism:**
  1. `server-fuzz` sends `{"__proto__":{"isAdmin":true}}` and only checks `res.status >= 500`, stack traces, and `ctype.includes("text/html")`. If the server actually pollutes `Object.prototype` and returns `200`, or reflects `<script>alert(1)</script>` with no `Content-Type` header (browser HTML-sniffs it), `server-fuzz` reports **`PASS: survived XSS/SQLi/proto-pollution fuzzing`**.
  2. `server-idor` never runs a **negative control** (checking that User A *can* `GET` the resource it just created). A typo in `resourcePathTemplate` (`/api/wrong-route/{id}`) returns `404` for User B and reports **`PASS`**. It also only probes `GET`, never `PATCH`/`PUT`/`DELETE` (contradicting `one-shot/modules/app.md:8`).
- **Live probes (CONFIRMED 2026-11-26):**
  - **P12:** Server that executes `Object.assign(Object.prototype, obj.__proto__)` and echoes `<p>` + raw XSS body with no `Content-Type` header → `server-fuzz` returned **`PASS`** (`1 endpoint(s) survived XSS/SQLi/proto-pollution fuzzing`).
  - **P10:** `idorProbe` pointing at nonexistent `/api/wrong-route/{id}` → `server-idor` returned **`PASS`** (`User B GET /api/wrong-route/1 -> HTTP 404`).
- **Fix:**
  - In `server-fuzz`: fail XSS reflection when `ctype` is `text/html`, `application/xhtml+xml`, or **empty/missing**; stop claiming `"proto-pollution"` unless an explicit canary/property check verifies it (honest scope: `"XSS/SQLi-error/500 fuzzing"`).
  - In `server-idor`: require User A `GET` to return `2xx` first (control probe), fail if `resourcePathTemplate` lacks `{id}`, and optionally probe `DELETE`/`PATCH` as User B.

#### V5 — **High (Brownfield Guard Bypass)** — Classes 3, 4: `countTestDefinitions` counts `test.skip`, `it.todo`, and string literals; `minTestDelta` silently defaults missing `baseline.json` to `0`
- **Where:** `one-shot/scripts/verify.mjs:144-161, 709-721`
- **Mechanism:**
  1. Line 156 matches `(?:test|it)(?:\.(?:only|skip|todo))?\s*\(` — explicitly counting **skipped and todo tests** toward `minTestCount`!
  2. `stripComments()` preserves string literals, so `"test('fake', () => {}); it('fake2', () => {});"` inside a test file is counted as 2 real tests.
  3. Line 712: when `contract.minTestDelta` is set and `baseline.json` is missing, it silently treats `baseline.testCount` as `0` instead of failing (unlike `diff-scope` at line 673, which fails loudly when `baseline.json` is missing).
- **Live probes (CONFIRMED 2026-11-26):**
  - **P4:** File with 0 active tests (`test.skip`, `it.todo`, plus a string containing `test(` and `it(`) → `countTestDefinitions()` returned **`4`**.
  - **P5:** `contract.json` with `minTestDelta: 1` and NO `baseline.json` on a 1-test project → `test-count-floor` returned **`PASS`** (`1 >= 1`).
- **Fix:** Exclude `.skip` and `.todo` from `countTestDefinitions` (only count active `test`/`it` or `.only` — or fail on `.only` too!). Strip quoted string literals before matching test calls. Fail `test-count-floor` loudly when `minTestDelta` is configured and `baseline.json` (or `baseline.testCount`) is missing.

#### V6 — **High (Deliverables & Diff-Scope Bypass)** — Classes 1, 3, 4: `deliverables` accepts directories and `../` path traversal; `diff-scope` fails on `./` prefix and ignores newly created `protectedFiles`
- **Where:** `one-shot/scripts/verify.mjs:654-663, 666-707`
- **Mechanism:**
  1. `fs.existsSync(path.join(root, rel))` accepts `"."`, `"../"`, and directories as "deliverables present on disk".
  2. `allowedFiles: ["./server.js"]` fails to match `path.relative(root, f)` (`"server.js"`) because leading `./` is not normalized.
  3. When only `protectedFiles` is set (`allowedFiles: null`), creating a file listed in `protectedFiles` that wasn't in `baseline.files` is not checked.
  4. Corrupt `baseline.json` (invalid JSON) is caught silently (`baseline = null`) and misreported as `"baseline.json is missing"` (Class 6).
- **Live probes (CONFIRMED 2026-11-26):**
  - **P6:** `deliverables: [".", "../"]` → `deliverables` returned **`PASS`** (`2/2 deliverable(s) present on disk`).
  - **P8:** `allowedFiles: ["./server.js"]` with modified `server.js` → `diff-scope` returned **`FAIL`** (`unwhitelisted edit: server.js`).
- **Fix:** Resolve each deliverable with `path.resolve(root, rel)`, assert it stays inside `root` (`!rel.startsWith("..") && !path.isAbsolute(rel)`), and require `statSync(full).isFile()`. Normalize `allowedFiles`/`protectedFiles` with `path.posix.normalize(...)` stripping leading `./`. Surface `baseline.json` parse errors distinctly from missing files.

#### V7 — **High (DOM Audit False Green)** — Classes 3, 4, 8: `contrastRatio` ignores `rgba()` alpha; `auditDomElements` ignores unloaded images; `runBrowserCheck` audits DOM only at 1280px and ignores 4xx/5xx network errors
- **Where:** `one-shot/scripts/verify.mjs:191-267, 349-437`
- **Mechanism:**
  1. `parseRgb()` ignores the 4th alpha component of `rgba(r, g, b, a)`. Semi-transparent text `rgba(0, 0, 0, 0.1)` on white (real contrast ~1.25:1, unreadable) is scored as solid black on white = **21.00:1 PASS**. `effectiveBg()` similarly stops at translucent layers without alpha-compositing.
  2. `auditDomElements()` checks `else if (img.complete && img.naturalWidth === 0)`, so an image that failed/never finished loading (`complete: false`) silently passes, and an image missing `alt` AND broken only reports missing `alt`.
  3. `runBrowserCheck()` loops viewports `[360, 768, 1280]` for overflow, then snapshots DOM only once at `1280px` — missing mobile-only contrast/dead-control bugs. It also never tracks failed network responses (`page.on("response", r => r.status() >= 400)`), contradicting `one-shot/modules/web.md:16`.
- **Live probe (CONFIRMED 2026-11-26):**
  - **P7:** `contrastRatio("rgba(0, 0, 0, 0.1)", "rgb(255, 255, 255)")` returned **`21`** (`browser-contrast: PASS`); image `{ complete: false, naturalWidth: 0, alt: "ok" }` returned **`browser-assets: PASS`**.
- **Fix:** Parse alpha in `parseRgb()` and alpha-composite `fg` over `bg` (and in `effectiveBg()`). Flag `!img.complete || img.naturalWidth === 0` as broken image independently of `alt` check. Add `page.on("response")` / `requestfailed` tracking and audit DOM at mobile (`360px`) + desktop (`1280px`).

#### V8 — **High (Env Exposure & False Fail)** — Classes 4, 17: `env-gitignore` misses nested `.env` files (`backend/.env`) and rejects valid `**/.env` ignore rule
- **Where:** `one-shot/scripts/verify.mjs:86-95, 772-787`
- **Mechanism:** `verify.mjs` only checks `path.join(root, ".env")` (ignoring monorepo/nested `backend/.env`), and `gitignoreIgnoresEnv` regex `/^\/?\.env\*?$/` rejects valid `**/.env` and `.env.*` patterns.
- **Live probe (CONFIRMED 2026-11-26):**
  - **P9:** `.gitignore` with `**/.env` + root `.env` → **`FAIL`** (false positive); `backend/.env` with empty `.gitignore` → **`PASS`** (false negative).
- **Fix:** Scan all `.env` files in `allFiles` (not just root) and accept `(?:\*\*\/)?\/?\.env\*?$` in `gitignoreIgnoresEnv`.

#### V9 — **High (Destructive CLI / Uncaught Crashes)** — Classes 6, 8: `init --git-hook` silently clobbers existing pre-commit hook and crashes on git worktrees; `install --with-hook` crashes on corrupt `settings.json`
- **Where:** `bin/one-shot.mjs:121-142, 266-277`
- **Mechanism:**
  1. `cmdInit --git-hook` overwrites `.git/hooks/pre-commit` unconditionally — destroying existing project hooks (Husky, lint-staged, custom hooks) even without `--force`.
  2. In a git worktree or submodule, `.git` is a regular **file** (`gitdir: ...`), so `fs.mkdirSync(path.join(root, ".git", "hooks"))` throws an uncaught `EEXIST`/`ENOTDIR` crash.
  3. `installClaudeStopHook()` calls `JSON.parse()` with no `try/catch` and no root-object check, crashing with a raw stack trace on malformed/JSONC `~/.claude/settings.json`.
- **Live probes (CONFIRMED 2026-11-26):**
  - **P13:** Existing `.git/hooks/pre-commit` (`CUSTOM_HOOK`) was silently overwritten (`clobbered: true`, exit `0`); worktree `.git` file crashed with uncaught `node:fs` error (exit `1`).
  - **P14:** Malformed `.claude/settings.json` crashed `install --with-hook` with uncaught `SyntaxError` (exit `1`).
- **Fix:** Refuse to overwrite an existing non-`one-shot` `pre-commit` hook without `--force` (or append/chain cleanly). Resolve the real git dir via `git rev-parse --git-path hooks` (falling back to `.git/hooks` only when `.git` is a directory). Wrap `settings.json` parse in `try/catch` with a clear error message and write via temp-file + rename.

#### V10 — **High (POSIX Process Leak & Startup Latency)** — Classes 8, 20: `killProcessTree()` orphans server processes on Linux/macOS; `waitForServer()` hangs 10s on immediate crash
- **Where:** `one-shot/scripts/verify.mjs:321-347, 442-459`
- **Mechanism:** `probeServer()` spawns `startCmd` with `shell: true`. On POSIX, `child.pid` is `/bin/sh`, so `child.kill("SIGTERM")` kills the shell and leaves the child server orphaned and holding the port. Additionally, if `startCmd` exits immediately with an error, `waitForServer()` ignores the `exit` event and polls for the full 10,000ms timeout.
- **Status:** **PLAUSIBLE (code-verified; Windows host cannot run POSIX branch directly)** — mechanism is standard Node `child_process` behavior on POSIX.
- **Fix:** Pass `detached: process.platform !== "win32"` to `spawn()` and kill the process group via `process.kill(-child.pid, "SIGTERM")` (with `SIGKILL` fallback). Pass `child` into `waitForServer()` so early exit aborts immediately with `stderrTail`.

#### V11 — **High (Live Windows Test Failure)** — Class 8: `scripts/audit_history.py` fails `test_quoted_utf8_filename_reports_real_name` on Windows (`cp1252` vs `utf-8`)
- **Where:** `scripts/audit_history.py:403-407`
- **Mechanism:** `stream.reconfigure(errors="replace")` keeps Windows' default `cp1252` encoding on piped `stdout`. Printing `café.md` emits raw byte `0xe9` (cp1252) instead of UTF-8 `0xc3 0xa9`, crashing `test_audit_history.py`'s UTF-8 reader thread with `UnicodeDecodeError` and `TypeError: unsupported operand type(s) for +: 'NoneType' and 'str'`.
- **Live reproduction (CONFIRMED 2026-11-26):** `python -m pytest scripts/test_audit_history.py` → `FAILED EndToEndTests::test_quoted_utf8_filename_reports_real_name`.
- **Fix:** `stream.reconfigure(encoding="utf-8", errors="replace")` in `scripts/audit_history.py:405`.
