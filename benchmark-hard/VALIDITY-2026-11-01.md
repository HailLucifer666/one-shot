## Tool findings fixed before the runs (fail-then-pass evidence)

1. **run_h5.mjs C7 was structurally broken on Node ≥ 20** (this machine: Node 24): it parsed TAP
   summaries from `npm test`, which emits the spec reporter — captured verbatim on the untouched
   starter BEFORE the fix: `npm test exit 0, NaN/NaN passing` + `NaN tests found`. So the runner
   failed every candidate including a perfect one. Fixed: forces `npm test -- --test-reporter=tap`
   (same tests, same exit semantics), parses both summary formats, adds an evidence note when the
   summary is unparseable. **Consequence:** the author's README claim "passes on a reference
   solution" was unverifiable as delivered (the reference is absent from disk, and this bug means
   it cannot have passed on this Node). The claim is now true and proven: a reference solution
   built for this validation (kept outside the pack, shas in PRE-REGISTERED) scores 7/7 exit 0;
   the starter yields exactly the designed fail-shape C1–C5 FAIL / C6 PASS / C7 FAIL (13 tests,
   needs >13) with real numbers.
2. **check_h1.py did not run under the documented `python`** (3.9 SyntaxError: backslash inside an
   f-string expression, line 69 — captured verbatim). Fixed; `python` (3.9) and `py` (3.14) now
   produce byte-identical output on all probes.
3. **check 12 false-FAIL** (bare `placehold` substring matched `placeholder="..."` — captured on
   the ember-oak sample: `FAIL [] ['placehold']` with no remote images present). Fixed by deriving
   the rule instead of a denylist: any img src/srcset or CSS url() that is not a local relative
   path or data: URI fails. ember-oak flips to 8/15 with check 12 PASS; everything else unchanged.
4. **Unencoded reads** (check_h1, check_h3, blind_rate): UTF-8 with replacement — emoji checks no
   longer depend on the Windows code page.

## Scorer lesson recorded (the pack's first)

My first manual C5 check was a **false FAIL by the scorer**: I probed with a task due 2026-10-31
calling it "yesterday" — but the harness browser clock at 04:50 IST makes the UTC date 2026-10-31,
and due ON today is not overdue. The page's code was correct (identical definition to the server,
which had already passed the clock-safe hidden tests). Re-probed with a clock-safe date
(2000-01-01): the overdue highlight works (li class " overdue", "(overdue)" label). Same class as
the three v0.1 checker false-FAILs: measure the premise before scoring the code.

Relatedly: run_h5's C5 auto-part passes on **string presence** ("overdue" in the HTML) regardless
of behavior — a proxy that would have stayed green even if the highlight were broken. The manual
half is load-bearing; consider a behavior-level C5 check (hidden test against a served page) so
the proxy cannot stand alone.
